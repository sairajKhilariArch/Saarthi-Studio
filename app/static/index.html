Autonomous coding

          
Agent runs

          
Give the agent a goal for the open workspace and it plans, lists, reads, edits files and runs build/test commands one step at a time — pausing for your approval before anything risky. Every step is logged here and survives restarts; a crash leaves the run marked interrupted, never half-repeated.

Diagnostics

          
Readiness

          
Whether Studio can work right now. The database and a writable data directory are required; a provider without a key, a failed router install or an unhealthy MCP server changes what works, not whether the app runs. Nothing here probes the network — measured state lives in the Router view and the Provider health card.

          

          
    
          
    
            
          
    
          
    Timeline
    
          
    What Studio actually did, newest last: provider requests, permission decisions and agent runs in one timeline. Each row carries the run, project or conversation it belongs to. Prompts, file bodies and key values are never stored here, and the support bundle redacts what a provider returned before it leaves this machine.
    
          
    
            
            
          
    
          
    
            
            
          
    
          
    
          
      
          
      Process log
      
          
      Every line is appended to studio.log beside the database as it happens, so an entry survives a crash that never reached the timeline. Newest last, redacted and clipped exactly as the support bundle is.
      
          
      
            
          
      
          
        
          
        

          
        
          
        Permissions
        
          
        Rules saved here decide what the agent and the router manager may do. A rule can only make an action stricter: a run started without write access still cannot write, even where a rule allows it. Reads default to allowed; anything that can destroy, spend or expose asks first.
        
          
        
            
            
          
        
          
        
            
            
          
        
          
        
            
            
            
          
        
          
        Rules in force
        
          
        
          
        Recent decisions
        
          
        Rule changes, refusals and approved installs, newest first.
        
          
          
          
          

          
          
          
          MCP servers
          
          
          Local Model Context Protocol servers this computer may run or reach. A server is a local command or a remote http(s) endpoint; its tools are checked against Permissions before anything runs, so an unlisted tool asks first.
          
          
          
            
            
          
          
          
          
            
            
          
          
          
          
            
            
            
          
          
          
          
          
            
            
            
            
          
          
          
          
          
          Registered servers
          
          
          Health is this session's own observation: a server is checked when you test it, press Check health, or a run uses it. Logs are the server's stderr plus what this app did — they stay in memory, hold the newest 200 lines, and show whatever the server chooses to print.
          
          
          
          
          Tools
          
          
          Test a server to discover what it offers. Nothing is cached: a test is a real handshake with a real process.

          One-time router setup
          
            
            
              
          1. Open your router dashboard (FreeLLMAPI usually runs on http://localhost:3001).
            2. 
              
          2. Add free-tier provider credentials in its Keys / Providers page.
            3. 
              
          3. Enable and order a fallback chain.
            4. 
              
          4. Copy the router's unified API key into the field above, then test the connection.
            5. 
            
          
            
          Free tiers have provider-defined quotas. Fallback only works while another enabled provider has capacity and the router recognises the error as retryable.
          
          
          

          
          
            
          Workspace & privacy
          
            
          Studio reads and writes only inside the folder you explicitly open, keeps chats in local SQLite at ~/.local/share/saarthi-studio, and never uploads files anywhere else. Code is sent to your configured router only when you attach it to a message.
          
            
          The editor does not run code, open a terminal, or touch files outside the open folder.

The interface server is the same one that opens in your browser at http://127.0.0.1:8666.
