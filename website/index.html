Everything a studio needs

Real server-side features, not mockups — the same UI powers the desktop window, the browser and the VS Code extension.

🧵

Threads & projects

Conversations persist in SQLite under the active project. Switching threads or projects never mixes answers — replies stream in live, no refresh needed.

🖼️

Media attachments

Attach images, audio or video to a message; stored with the thread and folded into the newest turn for models that accept them.

🌐

Deep search

Researches your question with planned web queries or a provider's built-in tools, streams each step, replies with cited sources.

📁

Projects & files

Open any local folder, browse the tree and edit in tabs with atomic saves. Workspace access is confined to the folder you open.

⚡

Skills

Local SKILL.md packs discovered, enabled and injected into chat — attach one per message or let keyword auto-suggest propose it.

📊

Usage analytics

Every request logged with latency, tokens and cost signals; the Usage page paginates, sorts and charts them.

How to use

Five steps from launch to working model.

Launch the studio

The window and the website are the same UI at http://127.0.0.1:8765.

Connect a provider

Provider setup points at FreeLLMAPI (Docker) or any OpenAI-compatible preset — Hugging Face, OpenRouter, Groq, Gemini and more. The router's unified key goes in Router settings; keys stay in a 0600 local file.

Pick a project, start a thread

Use the top-left selector, then start a thread in the composer. Everything below filters to the active project.

Compose with real controls

Plan mode for proposals, per-message model choice, skill chips, attachments, and Deep search when a question needs sources.

Work in the panels

Bottom-panel terminal for commands, resizable file editor beside the chat, Usage page to watch tokens and cost. Headless mode serves the website only: FREE_AI_STUDIO_NO_GUI=1.

Installation
