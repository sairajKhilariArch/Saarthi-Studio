`Mitigated` = guarded but the underlying cause remains.

| 19 | A paused run accepted a second pause that was never honoured; the runs panel did not refresh on agent events | **Fixed** (1.52.0) | A parked loop released its control entry by run id, so a resume that registered the next loop first had its control deleted; later pauses answered `200` with `pauseRequested: true` and were never read. Release is now identity-checked and the loop reads its own flag. The panel gated its event refresh on `state.view === "runs"`, which `state.view` (the left rail) never holds, so the board and cards only changed on manual Refresh; `refreshRunsPanel` now re-reads the list and the open run's step log. |
| 20 | Concurrent agent runs share one workspace with no locking | **Mitigated** (1.53.0, 1.54.0) | `app/src/filelock.rs` leases a path to a live run and refuses a `write` that another live run claimed or that would overwrite content this run never read, as a non-fatal `write-conflict` step. Still open: the lease covers the agent's own `write` only, so a command step, an editor save or another program edits files behind it (caught afterwards by the fingerprint check); there is no worktree per run; and both the ledger and the dispatcher are in-process, so a headless server and a desktop build pointed at one database admit independently. Because of that `max_concurrent_runs` still defaults to 1 and is clamped to 4. |
| 23 | Run restore is not a workspace snapshot | Open (1.70.0) | Restoring a finished run puts back only the files the run itself wrote, using the earliest pre-write checkpoint per path. Files changed by commands or other programs during the run are not included, old content over 200 000 characters is not checkpointed, and checkpoints written before 1.71.0 carry no digest, so those paths still restore without a changed-content check; new checkpoints skip an edited path unless the user forces it. |
| 22 | Build/test runs are deliberately narrow | Open (1.67.0) | Only the detected presets run: `cargo build`/`cargo test`, or `scripts.build`/`scripts.test` through npm/pnpm/yarn. There is no debugger, no watch mode, no arbitrary command box, and a compiler message with no file location stays in the raw output rather than becoming a Problems row. A run blocks its request for up to 300 s (the browser shows the pending state). |
| 21 | Git writes exist, but not the whole loop | Open (1.69.0) | The pane can stage, unstage, discard, commit, branch, read history, fetch, fast-forward pull, push, stage or unstage a whole hunk, and show a commit's own diff. It cannot merge or rebase, stage individual lines inside a hunk, or create a worktree checkpoint before an agent writes; merge conflicts are identified (grouped, flagged) but resolved manually in the editor. Remote authentication must already be configured: `GIT_TERMINAL_PROMPT=0`, so the app never asks for a password and a missing credential is a 502. `git commit` also depends on the repository having a `user.name`/`user.email`; git's own message is surfaced rather than a Studio prompt. |
| 16 | No Windows installer / macOS bundle / auto-update | Open | Phase 18. Portable zip and unsigned tarball only. |
| 18 | Phase 1 install smokes and dead tags still open | Open | Only the Windows zip has been launched locally; `v1.26.0/1/2` remain published without assets. |
| 24 | Diagnostics are a projection, not a log | Open (1.72.0) | `GET /api/diagnostics` reads `request_log`, `permission_audit`, `agent_runs` and failing `agent_steps`; nothing is written to a log file and the console has no ring buffer, so a crash before the row is committed leaves no trace. Router installs (`router-installs.json`) and MCP sessions (in memory) are not in the timeline. A terminal command, a Git call or a settings save has its own audit row but no request id tying it to the HTTP call that triggered it. The bundle is bounded to the newest 100 rows, so a long session is summarised by counts rather than by its whole history. |
| 25 | Redaction is conservative, not a proof | Open (1.72.0) | The value scan catches prefixed keys, bearer tokens, sensitive `name=value` pairs and long opaque runs; a secret split across whitespace, embedded in prose without a marker, or shorter than the pattern thresholds would pass through. It is applied to timeline details and the whole exported bundle, never to the live panels, which read the same rows the old UI always did. |
