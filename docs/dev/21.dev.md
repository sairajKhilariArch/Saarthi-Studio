# Development workflow for Saarthi-Studio on 21.dev

Development host: **21.dev**. The workstation is 21.dev; all commands below run inside that workspace.

## Where the code lives

| Area               | Language / stack                                    | Notes                                                       |
| ------------------ | --------------------------------------------------- | ----------------------------------------------------------- |
| `app/`             | Rust + SQLite                                       | The desktop / host app server.                              |
| `vscode-extension/` | TypeScript (hand-rolled ES modules, served from disk) | Built-in VS Code server. No build step or package manager. |
| `website/`         | Astro (frozen)                                      | Do not touch; last release commit `332bae4`.                |

## One-command sanity check

```bash
# 1. Application server
cargo run --manifest-path app/Cargo.toml

# 2. Extension: type-check
cd vscode-extension
npx tsc --noEmit -p tsconfig.json

# 3. Extension: build + focused test
node build.mjs --with-tests
node --test test/permissions.test.mjs
```

## Adding a feature

1. Read `docs/FEATURE-STATUS.md` / `docs/MASTER-ROADMAP.md` and pick the first
   NOT STARTED / IN PROGRESS item (work top-down, don't replan).
2. Implement only the missing pieces on every side the plan names. Anything
   already wired in `app/src` or the extension's `permissions.ts` is done —
   do not re-implement it.
3. Track the change on the wire-language model (type + action set + every
   predicate that gate-checks it; a stale predicate silently rejects a valid
   grant).
4. Add a focused test that only covers the new behaviour.
5. Rebuild the extension **before** running its tests (tests import `dist/`,
   which is stale until a fresh bundle).
6. Run the focused test file, not the whole suite — `test/lib.test.mjs` leaves a
   server open and the full `npm test` hangs at exit. Pre-existing; unrelated to
   the change.
7. Verify `tsc` and build, then `git add` + `git commit`, then confirm with
   `git log` + `git status`.

## Commit style

- Version first, then a short description, e.g. `2.6.1: extend the ...`.
- No `Co-Authored-By`, no "Generated with" trailer.
- Website changes are frozen and never committed here.

## Notes for the 21.dev agent session

- Run the **desktop app** (`app/`) and the **extension** (`vscode-extension/`)
  in separate terminals; they share `SAARTHI_STUDIO_HOME` under
  `~/.config/SAARTHI-STUDIO`.
- Postgres/SQLite: SQLite (`app/` data) is the default for local dev; do not
  point `database_url` at a remote Postgres except for a hosted app run.
- Use the permission model as the guard: the extension's `permissions.ts` and
  the desktop `app/src/permissions.rs` share the same 11 action names. Keep
  both in sync when adding a new action.
